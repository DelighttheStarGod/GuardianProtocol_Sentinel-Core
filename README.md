# 卫戍协议 · Guardian Protocol: Sentinel Core

> 把「1–4 人合作自动塔防 + 自走棋」的玩法搬进 Minecraft 的 **Forge 1.20.1 前置模组（core）**。
> 角色不用方块或骨骼建模，而是用 **2D 像素小人（公告板面片）** 呈现：**部署阶段摆好棋子，开打之后战斗全自动**。

## 一、这是什么

本模组是一个**前置模组（core）**，只负责塔防玩法的**底层能力**，把可复用的部分封装成下游模组能直接依赖的接口：

| 本项目负责 | 留给下游项目 |
|---|---|
| 职业 / 分支模板与数据 | 塔防循环（准备 → 出怪 → 协防 → 结算） |
| 棋子实体、渲染与战斗结算 | 商店买卖、费用系统 |
| 阻挡、拉怪、嘲讽、保护目标 | 羁绊 / 阵容加成 |
| 出怪点方块与出怪服务 | 角色导入、养成 |
| 技能状态机（技力 / 持续 / 弹药 / 槽位） | 技能的具体效果 |
| 数据包扩展与 `com.guardianprotocol.api` 门面 | — |

几个刻意的设计取舍：

- **一个实体类型装下所有职业**。`guardian_protocol:pixel_unit` 是唯一的 `EntityType`，职业由同步字段决定加载哪张贴图。新增一个分支不需要新注册实体，注册表干净，也不增加网络同步负担。
- **不做 3D 模型**。角色是一张正面像素图，渲染时永远正对镜头。代价是没有转身动画、不能绕到背后看，收益是新增角色的美术成本低到只需一张 PNG。
- **战斗全程自动驾驶**。玩家在部署阶段决定「谁站在哪、朝哪边」，之后索敌、出手、阻挡、治疗都由模组自己跑。

## 三、安装

1. 安装对应 1.20.1 的 **Minecraft Forge 47.4.23+**。
2. 把 `GuardianProtocol_Sentinel-Core-<版本>.jar` 放进 `.minecraft/mods/`。
3. 启动游戏。安装到服务器时，客户端与服务端都要放同一个 jar。

进入游戏后，创造模式物品栏里会出现名为 **Guardian Protocol: Sentinel Core** 的标签页，里面是本模组全部方块、物品与刷怪蛋。

## 四、从源码构建

需要 JDK 17。工程自带 Gradle Wrapper，无需本机预装 Gradle。

```bash
git clone <仓库地址>
cd GuardianProtocol_Sentinel-Core

# Windows
gradlew.bat build

# Linux / macOS
./gradlew build
```

产物：`build/libs/GuardianProtocol_Sentinel-Core-<版本>.jar`（已 reobf，可直接放进 `mods/`）。

其它常用任务：

```bash
./gradlew runClient    # 带模组启动客户端
./gradlew runServer    # 带模组启动服务端
./gradlew runData      # 跑数据生成（同时是最省事的「模组能否加载」端到端检查）
```

> 若 JDK 17 不在 `JAVA_HOME` 里，请先设置，或改用 Gradle 的 `org.gradle.java.home`。
> 首次构建需要下载 ForgeGradle 与 Minecraft 依赖，耗时较长属正常。

## 五、内容一览

### 5.1 职业与分支

**8 个职业、共 72 个分支**，全部由数据表生成，每个分支一个刷怪蛋。

| 职业 | id | 定位 |
|---|---|---|
| 先锋 | `vanguard` | 近战位为主，阻挡 1–2，部署费用低，费用回复核心 |
| 近卫 | `guard` | 全近战位，分支最多，输出主力 |
| 狙击 | `sniper` | 全远程位，物理输出核心，阻挡固定 1 |
| 重装 | `defender` | 全近战位，部署费用最高，防护与阻挡 |
| 术师 | `caster` | 全远程位，法术伤害核心 |
| 医疗 | `medic` | 全远程位，治疗覆盖 |
| 辅助 | `support` | 远程位为主，支援 / 减速 / 召唤 |
| 特种 | `specialist` | 近战位为主，阻挡 0–2，机制最丰富 |

每个分支带一组模板数据：职业、中文名、阻挡数、攻击间隔、面板（生命 / 攻击 / 护甲）、攻击范围、索敌规则、出手方式、技能表。

### 5.2 方块、物品与实体

| 注册名 | 类型 | 说明 |
|---|---|---|
| `guardian_protocol:protect_target` | 方块 | **保护目标**。无碰撞箱、不可破坏、自带血量与嘲讽，接触即抹杀；右键打开嘲讽半径界面（16~160 格，16 档，逐方块独立） |
| `guardian_protocol:spawn_point` | 方块 | **出怪点**。每种怪一行，种类 / 数量 / 首延迟 / 间隔各自独立（最多 4 行）；右键打开配置界面 |
| `guardian_protocol:spawn_marker` | 物品 | 出怪位置标定器，用于给出怪点绑定具体坐标 |
| `<分支>_spawn_egg` | 物品 | 每个分支一个专属刷怪蛋，放置即为该分支的棋子 |
| `guardian_protocol:pixel_unit` | 实体 | 棋子本体。完全静止、不可推动（对齐盔甲架摆件的手感） |
| `guardian_protocol:pawn_projectile` | 实体 | 远程分支的投掷物，无视重力、追踪目标、命中那一刻才结算 |

### 5.3 命令

所有命令挂在 `/guardianprotocol` 下（单人存档需开启作弊 / 服务器需 OP）：

```text
/guardianprotocol selftest [场景名]     跑无头自验；带场景名只跑一个
/guardianprotocol selftest path         打印自验报告的文件路径
/guardianprotocol spawn <种类> <数量>   就地出一波怪（调试用）
/guardianprotocol list                  列出当前的保护目标与出怪点
/guardianprotocol clear                 清理本模组生成的实体
/guardianprotocol skill [槽位]          只读：查看棋子的技力 / 激活 / 弹药状态
/guardianprotocol block                 只读：诊断阻挡现场（谁被挡、为什么没被挡）
```

`skill` 与 `block` 都是**只读**入口：不带参数、不改任何状态，用来在实机上定位问题。

### 5.4 配置文件

首次启动后生成 `config/guardian_protocol-common.toml`：

| 段 | 键 | 默认 | 说明 |
|---|---|---|---|
| `protectTarget` | `maxHealth` | | 保护目标最大生命值，归零即失守 |
| | `tauntEnabled` | `true` | 是否强制范围内敌对生物把 AI 目标改为保护目标 |
| | `tauntRadius` | `48.0` | 新放置保护目标的嘲讽半径默认值（格） |
| | `scanIntervalTicks` | `20` | 嘲讽扫描间隔 |
| | `killOnContact` | `true` | 是否开启「接触即抹杀」 |
| | `killRadius` | `1.0` | 抹杀判定半径 |
| | `onlyHostile` | `true` | 只抹杀敌对生物 |
| | 白名单 / 黑名单 | 空 | 逐实体类型的抹杀豁免与强制规则，黑名单优先级最高 |
| `blocking` | 白名单 | `#monster` | **只有**列出的生物才会被棋子阻挡 |
| `pawnFacing` | `mode` | | 棋子布设朝向方案（统一朝正东 + 界面旋转 / 跟随放置时玩家面向） |

## 六、核心机制

### 6.1 像素棋子：公告板渲染

`PixelUnitRenderer` 直接继承 `EntityRenderer`，不建骨骼模型：

1. 取摄像机位置算 `atan2` 得到水平角 → 绕 Y 轴旋转面片；
2. 再绕 X 轴旋转抵消俯仰 → 面片永远完整正对镜头；
3. 输出 4 个顶点构成 1.8 格高、0.6 格宽的四边形，贴上该职业的 PNG；
4. 命名牌、阴影、受击闪红、精炼金色呼吸光效照常处理。

**改贴图的 UV 约定**：

```text
v=0 ┌──────────────┐  ← 贴图顶部 = 小人头顶
    │   像素小人    │
v=1 └──────────────┘  ← 贴图底部 = 小人脚底
    u=0            u=1
```

### 6.2 攻击范围

每个分支的攻击范围来自其**模板干员的真实范围 id**，几何形状由文档转出成形状表（`data/RangeShapes.java`），而不是随手画的矩形。放置棋子时可用攻击范围预览叠加层直接看到实际打击格。

### 6.3 索敌：打谁、打几个

默认是「攻击范围内最近的一个」。在此之上有一组来自分支数据的覆盖规则：

- **优先目标**：护甲最低 / 最重 / 空中优先 / 只打空中；
- **多目标**：打范围内全部、打被挡住的全部；
- **不攻击**：部分分支不参与自动攻击；
- **连续加权**：个别分支按多项权重打分挑目标，而不是单一判据。

医疗分支的「出手」是治疗而不是伤害，见 6.6。

### 6.4 出手方式

| 方式 | 表现 |
|---|---|
| 投掷物 | 生成 `pawn_projectile`，无视重力、追踪目标、粒子拖尾，**命中那一刻**才结算伤害 |
| 近战武器 | 挥臂动作 + `SWEEP_ATTACK` 刀光 + 劈砍音，伤害即时结算 |

攻击间隔 = 分支数据里的间隔 × 统一倍率（`2.0`）。常态攻击**不产生击退**：结算后会把目标的位移原样复位。

### 6.5 阻挡与拉怪

阻挡是**导航式**的，**全程不碰坐标**：

- 棋子挡住**最近的 N 个**敌人（N = 该分支的常态阻挡数），第 N+1 个自然放行；
- 做法是「下发寻路目标 + 锁攻击目标」，被击退后由敌人自己走回锚点，不会出现「每 tick 拽坐标」的拖拽感；
- 锚点做成可替换接口（默认实现 = 正前 1.3 格 + 横向 0.3 格），真正的锚点选择留给关卡设计；
- 阻挡**搜索范围**默认是棋子脚下那一格，个别分支扩展到九宫格；**谁能被挡**由配置白名单决定（默认 `#monster`）；
- **常态阻挡为 0 的分支没有碰撞箱**，敌人会直接穿过去——这类棋子只提供攻击范围，不提供实体障碍。

**拉怪**是让上述链条跑起来的前提：原版没有任何 AI 会主动把棋子选成目标，不给目标敌人就不会走过来。因此棋子每 tick 把自己**攻击范围内**的敌人锁成「来打棋子」，排在阻挡判定之前；不参与攻击的分支不拉怪。

**嘲讽让位**：被保护目标嘲讽的敌人一旦把棋子锁成攻击目标，嘲讽 `Goal` 会立刻让出 `MOVE` 旗标，否则它自己的原版近战 `Goal` 会被 priority 饿死——实机上表现为「被挡住却打不还手」。

### 6.6 嘲讽与保护目标

保护目标是塔防的失守条件：

- 无碰撞箱、发光、不可破坏，血量存在方块实体里；
- **嘲讽**：按配置间隔扫描半径内的敌对生物，把它们的 AI 目标重定向到保护目标；
- **接触抹杀**：进入判定范围的实体被清除，支持白 / 黑名单，黑名单优先级最高；
- 嘲讽半径逐方块独立，右键打开界面调整。

### 6.7 医疗 = 治疗

医疗职业的「出手」走的是治疗路径而不是伤害路径，规则逐条来自分支数据：

- 挑**当前生命值最低**的友方（不是百分比）；
- 部分分支治疗范围内全体，部分按连锁跳跃（每跳递减）；
- **自己也是候选**；
- **只对同队生效**，敌人一律不治；
- 部分分支（武者 / 收割者 / 不屈者）**不可被治疗**。

### 6.8 技能：技力 / 持续 / 弹药 / 槽位

技能的**状态机**已经完整，**具体效果尚未实现**（见第十节）：

- **技力回复**四种：自动（每 20 tick +1）、攻击回复、受击回复、被动常驻；
- 技力上限 = 消耗技力；支持**初始技力**预充、**满即自动释放**、**阻回**（激活期间不回复）；
- **四类持续**：瞬发 / 有限时长（秒 × 20 tick）/ 永续 / 弹药耗尽；
- **槽位**：棋子放下时自动装技能 1，可用命令切换；只有 2 个技能的分支会明确拒绝 3 号槽位并说明原因。

### 6.9 伤害乘区与攻击力倍率

两条**互斥**的轴，判据只有一条——**面板上能不能直接看见**：

| 轴 | 影响 | 面板 |
|---|---|---|
| **伤害乘区** | 只乘 `hurt()` 的入参（护甲之前） | 不变 |
| **攻击力倍率** | 走 `effectiveAttackDamage()` | 变（朝向界面会显示） |

两者不允许对同一次伤害乘两次。这一区分来自「原文写的是**攻击力**还是**伤害**」，逐条对照分支特性原文判定。

## 七、数据包：自定义分支

分支定义可以**新增**，也可以用 `replaces` **覆盖**内置分支的部分字段——覆盖是逐字段的，未声明的字段保留内置值。

文件位置：

```text
data/<命名空间>/guardian_branches/<名字>.json
```

示例（新增一个狙击分支）：

```json
{
  "class": "sniper",
  "name": "探针狙击",
  "block": 0,
  "attack_interval": 1.0,
  "stats": {
    "max_health": 33,
    "attack_damage": 7,
    "armor": 2
  },
  "targeting": {
    "priority": "air_first",
    "count": "multi_all",
    "attack": true
  },
  "vertical": "both",
  "attack_method": "projectile",
  "range": ["0,1", "0,2", "0,3"]
}
```

覆盖内置分支时加一行 `"replaces": "<内置分支 id>"` 即可。数据包分支在 `/reload` 后重新解析；解析失败的单个文件会被跳过并在日志里给出原因，不影响其它分支。

> 数据包的命名空间请用 `guardian_protocol`（modId），**不要**用仓库名——仓库名只是工程标识，含大写与连字符，不是合法的资源命名空间。

## 八、作为前置模组对外提供的接口

下游模组**只应接触 `com.guardianprotocol.api` 这一个包**，其余包视为内部实现，可能在不通知的情况下变动。

| 门面 | 用途 |
|---|---|
| `GuardianCore` | 模组版本与兼容口径 |
| `Branches` | 查询 / 遍历分支模板 |
| `Pawns` | 棋子实体的生成、归属与状态读写 |
| `ProtectTargets` | 保护目标的注册与查询 |
| `SpawnPoints` | 出怪点的读写与「按组出一波」入口 |
| `Blocking` | 阻挡白名单与阻挡状态查询 |
| `Skills` | 技能状态机入口 |
| `Talents` / `Modules` | 天赋与模组槽位（**只解析、不执行**，留待下游填充） |

版本口径：项目尚未正式发版，破坏性改动不抬版本号；正式发布后会遵循语义化版本。

## 九、无头自验

本模组自带一套**无头确定性自验台**：把存档放进 `self-test/`，无头启动服务端，模组在 `ServerStartedEvent` 里跑完全部场景、写出报告文件后自动关服——整条链「启动 → 自验 → 关服」无需人工干预。

```bash
# 全套场景
./gradlew runServer -Pselftest

# 只跑一个场景（日常推荐，全套要起服务器并观察 200 tick）
./gradlew runServer -Pselftest -PselftestScenario=block

# 指定一块干净平地作为场地
./gradlew runServer -Pselftest -Dguardianprotocol.selftest.base=100,64,100
```

Windows 用户也可以直接跑 `self-test\run-self-test.bat`：它会先构建、准备好 eula / server.properties / 数据包，再启动无头服务端，并在开跑前删掉旧报告。

报告写在 `self-test/guardianprotocol-selftest.log`，逐场景列出 `[PASS]` / `[FAIL]`。

覆盖的场景包括：出手间隔、棋子阶位与存档往返、数据包分支、出怪组、生成式入侵、索敌判定、多目标、阻挡、实体障碍、垂直攻击区间、技能状态机、攻击方式、群伤、治疗与队伍、停顿、伤害乘区、实机演示等。

> **注意**：`runServer -Pselftest` **不删旧报告**，报告是跨次累加的。跑之前请先删掉 `self-test/guardianprotocol-selftest.log`，或先数一遍报告里的 `--- scenario:` 行数，以免把两次运行的结果读成一个假总数。
>
> 自验不会放置或破坏任何方块，生成的实体跑完全部 `discard()`。但原版 `MinecraftServer.stopServer()` 仍会保存世界，所以跑完存档的时间戳会变。介意的话请先复制一份存档。

`self-test/datapack/` 是自验专用的世界数据包真源（含自验用的分支 JSON），每次运行都会整份重新同步进存档。

## 十、已知问题与未实现

**尚未实现（已登记、有位置）**：

- **技能效果**。状态机（技力 / 持续 / 弹药 / 槽位）已完整，效果本身仍是占位表现（音效 + 粒子 + 日志）。攻击力、攻击间隔、目标数、防御力、生命、治疗、攻击范围、停顿 / 脆弱 / 寒冷等一律未做。
- **召唤物 / 援军**。牵出实体生命周期，未做。
- **可充能 / 蓄力**。需要「技力上限 = 消耗 × X」，当前不解析效果文本。
- **天赋与模组槽位**只解析、不执行，槽位留空等下游填充。
- **保护目标的抹杀判定目前只覆盖方块附近一定高度**，正上方整列的敌人打不到（已登记待修）。
- **生成式入侵只做了配置层（S1）**：相位状态机（S2）、分页界面（S3）、奖励与实体修正（S4）未做。因此「配好了却不出怪」是当前正常状态。
- **塔防循环、商店买卖、羁绊、角色导入不在本模组**，属于下游项目。

**需要实机目视确认**（开发环境起不了客户端，只能做到编译级与服务端逻辑级验证）：

- 出怪点界面与嘲讽半径界面的**排版手感**（数据层与包编解码已验，界面本身未在真实客户端点过）；
- 精炼棋子的金色呼吸光效、投掷物的贴图观感与拖尾密度；
- 若干手感常量（弹速、命中半径、拖尾密度、多目标伤害系数）。

**已知的有意行为**（不是 bug）：

- 常态阻挡为 0 的棋子没有碰撞箱，敌人会直接穿过去；
- 常态攻击不产生击退；
- 被嘲讽的敌人一旦锁定棋子，嘲讽 `Goal` 会主动让位。
